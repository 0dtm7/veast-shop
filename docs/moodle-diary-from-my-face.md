# VEAST — дневник разработки для Moodle от моего лица

## Запись 1. Выбор идеи проекта

Я выбрал идею коммерческого веб-продукта VEAST — интернет-магазина одежды в эстетике streetwear / Y2K / techwear / chrome. Мне было важно сделать не просто учебную страницу, а сайт, который выглядит как реальный fashion e-commerce продукт.

Главная коммерческая цель проекта — довести пользователя до оформления заказа. Целевое действие можно измерить: пользователь выбирает товар, добавляет его в корзину, заполняет checkout-форму, а backend проверяет данные и сохраняет заказ в `PostgreSQL-базе заказов`.

Я выбрал именно интернет-магазин, потому что в таком проекте можно показать полный путь пользователя: главная страница, каталог, карточка товара, корзина, оформление заказа, подтверждение и backend-демонстрация.

Как UX-аналитик я определил целевую аудиторию, описал персонажей, пользовательские цели, сценарии и основной путь покупки.

Как frontend-разработчик я реализовал HTML, CSS и JavaScript-логику: каталог, фильтры, карточку товара, корзину, избранное, checkout и страницы проекта.

## Запись 3. Анализ пользователей и целевая аудитория

Я определил целевую аудиторию VEAST как пользователей 16–28 лет, которые интересуются локальными fashion-брендами, streetwear, Y2K и techwear-эстетикой. Для них важны сильные фотографии товара, понятная цена, размер, посадка, доставка и быстрый checkout.

Основные цели пользователей:

1. быстро понять стиль бренда;
2. найти подходящий товар;
3. проверить цену, размер, материал и посадку;
4. добавить товар в корзину;
5. оформить заказ без регистрации;
6. получить понятное подтверждение.

На основе этого я сделал сайт с коротким коммерческим путём: главная → каталог → товар → корзина → оформление заказа → подтверждение.

## Запись 5. Пользовательские сценарии

Я описал основной сценарий: пользователь видит бренд, заходит на главную страницу, понимает стиль VEAST через hero-блок и Drop story, открывает каталог, выбирает товар, смотрит карточку, добавляет товар в корзину и оформляет заказ.

Ключевой путь пользователя:

`Главная → Каталог → Карточка товара → Корзина → Оформление заказа → Подтверждение заказа`

Также я продумал проблемные сценарии:

- если пользователь ничего не нашёл в каталоге, показывается пустое состояние;
- если корзина пустая, сайт предлагает вернуться в каталог;
- если checkout заполнен неправильно, появляются ошибки по полям;
- если backend недоступен, пользователь видит сообщение об ошибке;
- если заказ создан успешно, он появляется в `admin-orders.html` и `PostgreSQL-базе заказов`.

## Запись 10. Backend-разработка

Я реализовал backend на Node.js. Сервер отдаёт статические страницы и API.

Основные backend-функции:

- API товаров;
- API заказов;
- API статистики;
- обработка POST `/api/orders`;
- серверная валидация заказа;
- проверка email, контактных данных, товаров, размеров и суммы;
- сохранение заказов в `PostgreSQL-базе заказов`;
- страница `admin-orders.html` для демонстрации заказов.

Таким образом, проект показывает полноценный процесс: frontend создаёт заказ, backend проверяет данные и сохраняет результат.
