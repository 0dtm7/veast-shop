# Дизайн-документ коммерческого веб-продукта VEAST

## 1. Название проекта
VEAST — интернет-магазин одежды и аксессуаров локального streetwear / Y2K / techwear-бренда.

## 2. Краткое описание идеи
VEAST — коммерческий сайт для продажи одежды: футболок, худи, лонгсливов, брюк, верхней одежды и аксессуаров. Проект ориентирован на пользователей, которые хотят быстро найти вещь в цельной визуальной эстетике, посмотреть фотографии, выбрать размер, добавить товар в корзину и оформить заказ. Визуальная основа: светлый фон, строгая сетка, холодные серые оттенки, chrome-графика, washed-фактуры и крупные fashion-фотографии.

## 3. Коммерческая цель сайта
Основное целевое действие — оформление заказа. Измеримая конверсия: пользователь переходит из главной страницы или каталога в карточку товара, выбирает размер, добавляет товар в корзину и отправляет checkout-форму. Результат фиксируется в интерфейсе подтверждения и в backend-хранилище `PostgreSQL-базе заказов`.

## 4. Модель заработка
Основной способ монетизации — продажа одежды и аксессуаров VEAST. Дополнительные механики роста: лимитированные drop-коллекции, предзаказы, платная доставка, промокоды, повторные продажи через избранное, Telegram-канал бренда и будущие коллаборации.

## 5. Целевая аудитория
Основная аудитория: молодые люди 16–28 лет, интересующиеся локальными брендами, streetwear, Y2K-эстетикой, минимализмом и покупками онлайн. Большая часть пользователей приходит с мобильного устройства из социальных сетей, поэтому интерфейс должен быть быстрым, адаптивным и понятным. Уровень дохода: средний и ниже среднего для студентов, средний для молодых специалистов. Каналы получения информации: Telegram, VK, TikTok, Instagram/Reels, рекомендации друзей и подборки брендов.

## 6. Персонажи пользователей

## 7. Пользовательские цели
- понять, что продаёт бренд и почему ему можно доверять;
- быстро перейти в каталог;
- найти товар через поиск, фильтр или категорию;
- посмотреть фото, цену, размеры, состав и уход;
- добавить товар в избранное;
- добавить товар в корзину;
- оформить заказ без регистрации;
- получить подтверждение действия;
- найти контакты, Telegram-канал и оферту и политику конфиденциальности.

## 8. Пользовательские сценарии
### Контекстный сценарий
Пользователь видит ссылку на VEAST в соцсетях, открывает сайт с телефона, попадает на главную страницу, оценивает визуальный стиль, нажимает «Каталог», выбирает категорию «Худи», сортирует товары, открывает карточку, проверяет размер и состав, добавляет товар в корзину, оформляет заказ.

### Сценарий ключевого пути
Главная → Каталог → Карточка товара → Выбор размера → Корзина → Оформление заказа → Подтверждение. Этот путь доступен без регистрации и без лишних шагов.

### Проверочные сценарии «А что, если...»
- Если корзина пустая, пользователь видит пустое состояние и ссылку обратно в каталог.
- Если пользователь не заполнил обязательные поля checkout-формы, форма не отправляется и показывает ошибки.
- Если backend недоступен, заказ дополнительно сохраняется в localStorage, чтобы не потерять действие пользователя.
- Если товар не найден по ID, открывается сообщение «Товар не найден».
- Если в избранном нет товаров, пользователь видит пустое состояние и переход в каталог.

## 9. Информационная архитектура
Выбрана гибридная структура. Каталог товаров имеет древовидную организацию по категориям: худи, футболки, лонгсливы, верхняя одежда, брюки, аксессуары. Карточка товара раскрывает информацию линейно: фото → название → цена → размеры → CTA → описание → состав → доставка → рекомендации «С чем носить». Избранное, похожие товары и рекомендации создают сетевые связи между объектами.

## 10. Карта сайта и основные страницы
- `index.html` — главная страница;
- `catalog.html` — каталог товаров;
- `product.html?id=...` — карточка товара;
- `cart.html` — корзина;
- `checkout.html` — оформление заказа;
- `thanks.html` — подтверждение заказа;
- `favorites.html` — избранное;
- `account.html` — личный кабинет / история заказов;
- `contacts.html` — контакты и форма обратной связи;
- `privacy.html` — оферта, пользовательское соглашение и политика конфиденциальности;
- `project.html` — страница проекта и дизайн-документ;
- `admin-orders.html` — backend-демонстрация заказов;
- `404.html` — страница ошибки.

## 11. Список функциональных блоков
Header, логотип-ссылка, главное меню, поиск, мобильное меню, hero-блок, Drop Story, каталог, фильтры, сортировка, карточка товара, карточка товара в каталоге, корзина, checkout-форма, подтверждение заказа, избранное, личный кабинет, контактная форма, блок доверия, Telegram-ссылка, футер, пустые состояния, сообщение об ошибке.

## 12. Описание навигации
Главная навигация содержит переходы в каталог, избранное, кабинет, контакты и проект. Логотип ведёт на главную страницу. Поиск доступен из шапки и каталога. Корзина доступна через иконку в header с любой страницы. Пользователь может попасть к покупке за несколько шагов: Главная → Каталог → Карточка товара → Корзина/Checkout.

## 13. Обязательные компоненты интерфейса
- навигационные: меню, логотип-ссылка, поиск, хлебные крошки, футер;
- информационные: карточки товаров, описание, состав, размерная сетка, статус наличия;
- сервисные: корзина, форма заказа, форма обратной связи, избранное, личный кабинет;
- дизайнерские: сетка, визуальная иерархия, единые кнопки, бейджи, состояния hover/active;
- коммерческие: CTA «В корзину», блок доверия, доставка, возврат, подтверждение заказа, Telegram-канал.

## 14. Требования к графическому дизайну
Дизайн должен оставаться минималистичным, но не пустым. Цветовая схема: белый фон, чёрный текст, серые линии, холодные светлые акценты. Шрифт: системный sans-serif для высокой читаемости. Сетка: строгая, с одинаковыми отступами и ровными карточками. Кнопка покупки заметная, но не кричащая. Декоративные элементы не мешают продаже. Фотографии товаров выдержаны в единой студийной подаче.

## 15. Описание frontend-части
Frontend реализован на HTML, CSS и JavaScript-модулях. Реализованы: адаптивная вёрстка, каталог, поиск, фильтры, сортировка, карточки товаров, второе фото при наведении, корзина, избранное, формы, клиентская валидация, сохранение состояния в localStorage, обработка пустых состояний и сообщений.

## 16. Описание backend-части
Backend реализован на Node.js без внешних зависимостей. Сервер отдаёт статические страницы и API. API поддерживает получение товаров, получение заказов, создание заказа и сохранение обратной связи. Данные заказов сохраняются в JSON-файлы. Реализована базовая серверная валидация.

## 17. План тестирования
Тестирование проводится на трёх этапах: бумажный прототип, интерактивный прототип, рабочий сайт. Для рабочего сайта проверяются сценарии покупки, поиска, фильтрации, избранного, checkout-формы, мобильного меню и ошибок. Нужно протестировать минимум 5 пользователей и зафиксировать время, ошибки, вопросы, эмоциональные реакции и результат.

## 18. Критерии готовности проекта
- сайт запускается локально;
- все основные страницы открываются;
- пользователь может найти товар и оформить заказ;
- корзина и избранное работают;
- backend сохраняет заказ;
- есть документация, карта сайта и план тестирования;
- есть адаптивная версия desktop/mobile;
- интерфейс соответствует выбранной визуальной системе;
- проект можно показать на защите как коммерческий веб-продукт.

## Важное уточнение по сравнению товаров
В исходном задании для интернет-магазина упоминается сравнение товаров. В текущей версии VEAST сравнение было убрано как лишний элемент интерфейса по продуктовой логике: для небольшого fashion-дропа из 9 товаров важнее быстрый выбор, избранное, рекомендации и оформление заказа. Если преподаватель будет строго требовать именно пункт «сравнение товаров», его лучше вернуть отдельной страницей перед финальной сдачей.
